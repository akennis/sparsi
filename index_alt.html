For developers & engineering leaders building agents

Your agent interprets.
Sparsi compiles.

Sparsi is a framework for building AI-powered MCP servers. It captures the request types your agent handles over and over — returns, status checks, plan changes — as compiled workflows: mostly deterministic code, AI only where judgment counts, with bounded cost and a per-step audit trail. The long tail still falls through to the agent, unchanged.

✓ Deterministic by default ✓ Audit record per operation ✓ Bounded token cost ✓ Unit-testable, no API key ✓ Single-file executable MCP server

The Core Idea

A build step your agent never had

An interpreter re-derives the routine on every run; a compiler pays that cost once. Today's agents are interpreters — Sparsi gives them the compile step.

🔁

Interpreted: re-planned every request

The agent rebuilds the whole routine from primitives every single time — so every "where's my order?" re-pays the reasoning cost in tokens, in latency, and in a fresh chance to get it wrong.

⚡

Compiled: planned once, run many

You author the routine once — classify, route, hit your systems in order, write the reply — and Sparsi compiles it into a fixed DAG. Every request after runs that path: less work, fewer tokens, right more often.

📈

The more Sparsi, the better. Every request type you capture as a tool moves more of the agent's traffic onto a deterministic, bounded-cost, audited path — while the primitives stay as the long-tail fallback. Read the concepts →

The Architecture

How a request flows through Sparsi

The user talks to your chatbot. The agent LLM recognizes the intent and forwards it to a Sparsi MCP server. Inside, an AI classifier routes the request through deterministic channels; a final AI node writes the reply, which the agent relays back. One boundary, crossed twice — and nothing else leaks across it.

🔑

The agent LLM and Sparsi's node models are different models. The chatbot's model only ever sees a tool call and a finished natural-language reply. Inside the workflow, Sparsi embeds its own AI with a purpose-fit model at each point — a cheap classifier here, a strong synthesizer there, an independent checker where it earns its keep — each chosen, versioned, and audited per workflow. The boundary is real: no prompts, no scratchpad, no intermediate state crosses it in either direction.

What You Get

Predictable, auditable, and cheap — by construction

These aren't options you tune. They fall out of capturing a known path as a workflow: deterministic by default, AI only where judgment is required.

🔒

Deterministic by Default

The same inputs produce the same outputs, forever. The bulk of every workflow is plain code you unit-test without ever calling a model.

🤖

AI Only Where It Earns It

AI runs only where no deterministic rule fits. Each AI step pins its own model and logs its exact input, output, and reasoning.

💰

Bounded, Predictable Cost

The number of AI calls is fixed by the workflow, not by input length or model mood. Cost is known before you run.

Get Started

Install the skills, then describe your workflow

The fastest path into Sparsi is the two Claude Code skills. Hand Claude a plain-English workflow description — it designs the DAG, generates the Sparsi program, and compiles a standalone MCP server.

terminal 
# 1 — install the skills (Claude Code & Gemini CLI)
cp -r sparsi-design  ~/.claude/skills/
cp -r sparsi-codegen ~/.claude/skills/

# 2 — design & generate from plain English
/sparsi-design  <describe your workflow>
/sparsi-codegen <paste the approved design> ./my-workflow

# 3 — register the compiled MCP server
claude mcp add my-workflow -- ./my-workflow/my-workflow -mcp
